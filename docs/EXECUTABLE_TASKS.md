# 斯诺克 3D 游戏可执行最小任务清单

## 0. 使用说明

本文件把 `DEVELOPMENT_PLAN.md` 拆成可以直接创建 Issue、分配给开发者并验收的最小任务。

### 任务规则

- 每项任务只产生一个主要结果。
- 如果任务不能在一个短迭代内完成，继续拆分，不要用“完成物理系统”这类大任务。
- 任务必须写清依赖、改动范围和验收条件。
- 任务完成后必须附带测试结果、截图、录屏或数据文件中的至少一种证据。
- 未完成自动化验证的物理任务，不标记为完成。

### 优先级

- `P0`：不完成就无法开始后续核心开发。
- `P1`：MVP 必须完成。
- `P2`：提升真实感、可维护性或训练体验。
- `P3`：正式版本、扩展内容或联机准备。

### 状态建议

```text
TODO -> IN_PROGRESS -> REVIEW -> DONE
                    \-> BLOCKED
```

## 1. 项目基线模块 `FOUNDATION`

### FND-001 建立仓库和独立 CMake 工程

- 优先级：P0
- 依赖：无
- 工作：创建项目仓库、CMake 工程、Visual Studio/MSVC 构建配置和基础目录；此任务不依赖 UE5。
- 产物：可在命令行编译的空 C++ 工程。
- 验收：干净目录可以生成并编译 Debug/Release 目标。

### FND-002 创建 UE5 工程和 Plugin 骨架

- 优先级：P0
- 依赖：FND-001
- 工作：在安装 UE5 后创建 C++ 工程，建立 `SnookerPhysics` Plugin、`SnookerGame` 模块和 Editor 模块；未安装 UE5 时先提交目录和接口设计，不标记编译完成。
- 产物：`.uproject`、Plugin 描述、`Build.cs`、模块入口和目录结构。
- 验收：安装 UE5 后可生成项目文件并编译 Development/DebugGame 目标。

### FND-003 建立资源目录规范

- 优先级：P0
- 依赖：FND-001
- 工作：建立 `UnrealProject/Content/Snooker/{Maps,Meshes,Materials,Animation,Audio,UI,Data,Debug}`、`UnrealProject/Source`、`UnrealProject/Plugins`、`PhysicsCore` 和 `RulesCore` 目录及命名规则。
- 产物：目录说明和示例资源。
- 验收：新资源能按规则放置，不出现临时资源散落在项目根目录；核心源码不放入 Content。

### FND-004 配置版本控制和大文件策略

- 优先级：P0
- 依赖：FND-001
- 工作：配置 Git LFS 或团队选定的 Perforce 目录；加入 Unreal 忽略规则，记录 UE5 版本、插件和编译工具链。
- 产物：版本控制配置、提交规范和二进制资源策略。
- 验收：工程克隆到干净目录后可以恢复；安装 UE5 后能生成项目文件并还原插件配置。

### FND-005 固定坐标与单位约定

- 优先级：P0
- 依赖：FND-001
- 工作：编写坐标、单位、角度、时间和 UE5 `FVector`/`FTransform` 转换规范。
- 产物：`SnookerUnits.h`、`SnookerCoordinateConvention.md`。
- 验收：独立核心和 UE5 适配层使用同一坐标约定；禁止出现未解释的厘米/米混用。

### FND-006 建立日志类别

- 优先级：P1
- 依赖：FND-001
- 工作：定义 Physics、Rules、Shot、Replay、Validation、Interaction 日志类别，兼容独立命令行、文件日志和 UE5 日志。
- 产物：统一日志宏或封装。
- 验收：一次击球可按类别过滤日志，正式版本可以降低日志级别。

### FND-007 建立自动化测试入口

- 优先级：P0
- 依赖：FND-001
- 工作：添加 CTest/自定义 C++ 测试基础入口，并预留 Unreal Automation Tests 命令行运行说明。
- 产物：至少一个通过的数学/数据测试。
- 验收：不安装 UE5 也能运行核心测试并返回失败代码；安装 UE5 后可运行 UE 自动化测试。

### FND-008 建立开发者调试开关

- 优先级：P1
- 依赖：FND-001、FND-006
- 工作：定义轨迹、碰撞点、接触法线、睡眠状态和物理步计数的调试开关。
- 产物：命令行参数、核心调试配置和 UE5 Developer Settings/控制台变量设计。
- 验收：无需改代码即可打开和关闭每一类可视化。

## 2. 独立核心和 UE5 适配模块 `CORE_ADAPTER`

### COR-001 定义纯 C++ 核心类型

- 优先级：P0
- 依赖：FND-001、FND-005
- 工作：定义 `Vec2d`、`Vec3d`、`Quatd`、`Transformd`、ID、时间和标量别名。
- 产物：`PhysicsCore/include/Snooker/Math`。
- 验收：核心类型不包含 Unreal 头文件，可在独立 CMake 目标中编译。

### COR-002 建立核心和规则目录

- 优先级：P0
- 依赖：FND-001
- 工作：建立 `PhysicsCore/include`、`PhysicsCore/src`、`RulesCore/include`、`RulesCore/src`、`tests`、`tools` 和 `data`。
- 产物：目录、CMake target 和最小源码入口。
- 验收：PhysicsCore、RulesCore、Tests、Tools 可以分别构建。

### COR-003 建立独立命令行测试运行器

- 优先级：P0
- 依赖：COR-001、COR-002
- 工作：创建可以加载参数、运行固定球局并输出 PASS/FAIL 的命令行程序。
- 产物：`snooker_validation` 可执行文件。
- 验收：不安装 UE5 也能运行一个空球局和一个数学测试。

### COR-004 定义核心配置文件格式

- 优先级：P0
- 依赖：COR-002
- 工作：定义桌面、球、布面、库边、袋口、球杆和求解器参数的 JSON/CSV 或纯文本格式。
- 产物：参数 schema、默认样例和版本字段。
- 验收：同一份参数可以被命令行工具和 UE5 适配层读取。

### COR-005 定义独立回放数据格式

- 优先级：P0
- 依赖：COR-002、COR-004
- 工作：定义初始快照、击球输入、参数版本、物理步长、事件序列和最终结果格式。
- 产物：`ShotRecord` schema 和样例文件。
- 验收：一杆记录不依赖 UE5 类型，可以保存和恢复。

### COR-006 建立独立 2D 轨迹可视化

- 优先级：P1
- 依赖：COR-003、COR-005
- 工作：读取 JSON/CSV 并显示桌面、球、轨迹、碰撞点、库边和袋口事件。
- 产物：本地 HTML/SVG 或轻量 C++ 2D 调试工具。
- 验收：没有 UE5 时可以观察至少一杆完整球路和事件时间轴。

### COR-007 建立 UE5 Plugin 接入接口

- 优先级：P0
- 依赖：FND-002、COR-002
- 工作：设计 `USnookerPhysicsSubsystem`、`USnookerBallComponent`、`USnookerTableComponent` 和事件转发接口。
- 产物：UE5 Plugin 公共接口设计和最小类骨架。
- 验收：UE5 安装后可创建 Subsystem，核心模块不反向依赖 UE5。

### COR-008 实现 UE5 类型转换层

- 优先级：P0
- 依赖：COR-001、COR-007
- 工作：实现 `Vec3d <-> FVector`、`Quatd <-> FQuat`、`Transformd <-> FTransform` 转换，并明确单位和坐标轴方向。
- 产物：适配层转换函数和转换测试。
- 验收：转换往返误差在设定容差内，核心层没有 Unreal 类型泄漏。

### COR-009 将核心源码直接编译进 Plugin

- 优先级：P0
- 依赖：COR-007、COR-008
- 工作：把 PhysicsCore/RulesCore 源码纳入 Plugin 的 Build.cs；暂不依赖预编译静态库。
- 产物：可编译的 `SnookerPhysics` Plugin。
- 验收：UE5 Development 和 DebugGame 配置可编译，独立 CMake 测试仍然通过。

### COR-010 建立 UE5 与独立结果的对照测试

- 优先级：P1
- 依赖：COR-005、COR-009
- 工作：在 UE5 中加载同一快照和击球输入，与命令行结果比较事件序列和最终球位。
- 产物：UE5 对照测试命令和报告。
- 验收：UE5 适配层只负责调用和呈现，不改变核心计算结果。

## 3. 数据和桌面几何模块 `DATA_TABLE`

### DAT-001 定义球数据结构

- 优先级：P0
- 依赖：FND-005
- 工作：定义独立核心使用的球 ID、球类型、半径、质量、材质引用和初始球位；再建立 UE5 `UDataAsset` 适配对象。
- 产物：`BallDefinition` 和 `UBallDefinitionAsset`。
- 验收：不安装 UE5 也可以序列化、反序列化并打印一个球的完整定义；安装 UE5 后可从 DataAsset 导入。

### DAT-002 定义球桌数据结构

- 优先级：P0
- 依赖：FND-005
- 工作：定义独立核心使用的桌面边界、布面边界、库边、袋口、球点和球位；再建立 UE5 `UDataAsset` 适配对象。
- 产物：`TableDefinition` 和 `UTableDefinitionAsset`。
- 验收：不修改代码即可创建另一套尺寸配置，命令行和 UE5 读取结果一致。

### DAT-003 定义布面参数资产

- 优先级：P0
- 依赖：DAT-001
- 工作：建立滑动摩擦、滚动阻力、旋转摩擦、睡眠阈值和布况字段；为 UE5 建立 `UClothProfileAsset`。
- 产物：`ClothProfile` 和 `UClothProfileAsset`。
- 验收：不安装 UE5 也可以在物理测试中切换不同布况参数。

### DAT-004 定义库边参数资产

- 优先级：P0
- 依赖：DAT-002
- 工作：建立恢复、切向、接触高度和袋口过渡参数；为 UE5 建立 `UCushionProfileAsset`。
- 产物：`CushionProfile` 和 `UCushionProfileAsset`。
- 验收：桌面几何不包含散落在代码中的库边参数，核心测试可以独立读取。

### DAT-005 定义袋口参数资产

- 优先级：P0
- 依赖：DAT-002
- 工作：建立袋口开口、袋角、袋底、进袋阈值和弹出参数；为 UE5 建立 `UPocketProfileAsset`。
- 产物：`PocketProfile` 和 `UPocketProfileAsset`。
- 验收：袋口参数可以独立调整并被独立测试读取。

### DAT-006 定义球杆参数资产

- 优先级：P1
- 依赖：DAT-001
- 工作：建立球杆长度、质量、杆头尺寸、最大后拉距离和最大冲量参数；为 UE5 建立 `UCueProfileAsset`。
- 产物：`CueProfile` 和 `UCueProfileAsset`。
- 验收：不同球杆配置能够改变击球输入限制，但不直接修改规则。

### DAT-007 建立桌面几何生成器

- 优先级：P0
- 依赖：DAT-002、DAT-004、DAT-005
- 工作：根据数据资产生成桌面、布面、库边和袋口的物理几何描述。
- 产物：运行时/编辑器几何生成器。
- 验收：改动桌面配置后可以重新生成几何，位置关系可视化正确。

### DAT-008 建立标准球位生成器

- 优先级：P1
- 依赖：DAT-001、DAT-002
- 工作：生成开局、重置彩球、训练球位和自定义球位。
- 产物：球位生成函数和测试数据。
- 验收：同一配置重复生成的球位完全一致。

## 4. 物理核心模块 `PHYSICS`

### PHY-001 定义物理球状态

- 优先级：P0
- 依赖：DAT-001
- 工作：定义位置、线速度、角速度、睡眠状态、半径和 ID。
- 产物：`BallState`。
- 验收：状态可复制、比较、序列化，并不依赖 Actor、Component 或其他 UE5 对象。

### PHY-002 实现固定时间步调度器

- 优先级：P0
- 依赖：FND-005、PHY-001
- 工作：实现独立于渲染帧率的固定物理步进。
- 产物：`PhysicsClock`。
- 验收：30、60、120 FPS 渲染下输入相同，物理步数量和结果一致。

### PHY-003 实现球状态快照

- 优先级：P0
- 依赖：PHY-001
- 工作：定义单杆前、单步中和单杆后的快照格式。
- 产物：`PhysicsSnapshot`。
- 验收：快照可以保存和恢复所有影响球局结果的状态。

### PHY-004 实现布面滑动摩擦

- 优先级：P0
- 依赖：PHY-001、DAT-003
- 工作：根据相对速度和布面参数更新线速度。
- 产物：摩擦求解函数。
- 验收：球会减速并在无旋转情况下稳定停止；结果可由测试读取。

### PHY-005 实现滚动阻力

- 优先级：P0
- 依赖：PHY-004
- 工作：实现纯滚动状态下的速度衰减。
- 产物：滚动阻力求解函数。
- 验收：滚动距离随参数变化单调变化，不能出现无输入加速。

### PHY-006 实现角速度更新

- 优先级：P0
- 依赖：PHY-004
- 工作：实现角速度积分、衰减和与布面的耦合。
- 产物：角速度更新函数。
- 验收：后旋、前旋和左右旋的状态可以独立观察。

### PHY-007 实现滑动到滚动转换

- 优先级：P0
- 依赖：PHY-004、PHY-006
- 工作：依据接触点相对速度判断状态并平滑切换。
- 产物：滚动状态判定器。
- 验收：高速击球不会瞬间跳成纯滚动；低速阶段不反复切换。

### PHY-008 实现睡眠判定

- 优先级：P0
- 依赖：PHY-005、PHY-006
- 工作：定义位置、线速度、角速度和持续时间阈值。
- 产物：睡眠状态机。
- 验收：球停止后最终状态稳定，极低速球不会永久消耗物理步。

### PHY-009 定义击球输入快照

- 优先级：P0
- 依赖：DAT-006、PHY-001
- 工作：记录球杆方向、击打点、后拉距离、出杆速度、杆头偏移和时间。
- 产物：`ShotInput`。
- 验收：同一输入快照可以在不同入口被重复模拟。

### PHY-010 实现球杆冲量映射

- 优先级：P0
- 依赖：PHY-009
- 工作：将球杆输入映射为母球初始线速度和角速度。
- 产物：击球冲量求解器。
- 验收：中心击球不产生非预期旋转；偏心击球产生方向一致的旋转。

### PHY-011 实现球-球宽相位检测

- 优先级：P0
- 依赖：PHY-001
- 工作：实现球对候选碰撞的空间检测。
- 产物：候选碰撞列表。
- 验收：候选列表不漏掉高速球，不重复输出同一球对。

### PHY-012 实现球-球连续碰撞时间

- 优先级：P0
- 依赖：PHY-011
- 工作：计算球体在一个物理步内的首次接触时间。
- 产物：连续碰撞求解函数。
- 验收：高速球不会在一个步长内穿过另一个球。

### PHY-013 实现球-球碰撞响应

- 优先级：P0
- 依赖：PHY-012、DAT-001
- 工作：更新两球的线速度、角速度和接触事件。
- 产物：球-球响应器。
- 验收：中心碰撞、薄碰和低速碰撞均不出现能量爆炸。

### PHY-014 实现碰撞事件记录

- 优先级：P0
- 依赖：PHY-013
- 工作：记录时间、球 ID、接触点、法线、相对速度和前后速度。
- 产物：`CollisionEvent`。
- 验收：回放日志可以还原一杆中所有球-球碰撞顺序。

### PHY-015 实现贴球状态

- 优先级：P1
- 依赖：PHY-013
- 工作：检测球是否贴球并输出规则需要的状态。
- 产物：贴球判定 API。
- 验收：贴球不被错误地当作一次新的明显碰撞。

### PHY-016 实现库边碰撞检测

- 优先级：P0
- 依赖：DAT-004、DAT-007
- 工作：根据库边轮廓检测球与库边接触。
- 产物：库边候选接触列表。
- 验收：桌面边界、库边顶部和过渡区能被区分。

### PHY-017 实现库边碰撞响应

- 优先级：P0
- 依赖：PHY-016
- 工作：更新球的法向速度、切向速度和角速度。
- 产物：库边响应器。
- 验收：一库、两库和旋转球碰库结果可记录并回放。

### PHY-018 实现袋口几何检测

- 优先级：P0
- 依赖：DAT-005、DAT-007
- 工作：实现袋口边缘、袋角、袋底的连续接触检测。
- 产物：袋口接触求解器。
- 验收：球擦袋角可弹出，进入袋底才触发落袋事件。

### PHY-019 实现落袋状态机

- 优先级：P0
- 依赖：PHY-018
- 工作：定义桌面、袋口、袋内、已落袋和弹出的状态转换。
- 产物：`PocketState` 和事件。
- 验收：落袋只触发一次，弹出球仍然回到桌面物理系统。

### PHY-020 实现物理步异常保护

- 优先级：P1
- 依赖：PHY-012、PHY-017、PHY-019
- 工作：检测 NaN、穿透、速度爆炸、超时和无穷碰撞循环。
- 产物：异常代码、日志和故障快照。
- 验收：异常能中断当前模拟并生成可重放文件，不让游戏永久卡死。

### PHY-021 建立物理服务接口

- 优先级：P0
- 依赖：PHY-001 至 PHY-020 中的核心项
- 工作：统一提供 `BeginShot`、`Step`、`IsSettled`、`GetEvents`、`SaveSnapshot`、`RestoreSnapshot`。
- 产物：`ISnookerPhysicsService`。
- 验收：游戏层不需要直接访问内部求解细节即可完成一杆模拟。

## 5. 物理实验和校准模块 `VALIDATION`

### VAL-001 创建物理实验地图

- 优先级：P0
- 依赖：DAT-007、PHY-021
- 工作：创建无 UI 的单球、球碰撞、库边、袋口实验区域。
- 产物：`Map_PhysicsLab`。
- 验收：可以通过开发者命令生成预设测试场景。

### VAL-002 创建轨迹可视化

- 优先级：P0

- 工作：保存 frame 状态、球位、比分、参数版本和游戏版本。
- 产物：存档格式和读写服务。
- 验收：关闭并重新启动后可以继续同一 frame。

### REP-005 添加版本迁移入口

- 优先级：P2
- 依赖：REP-004
- 工作：为未来修改字段建立存档版本和迁移函数。
- 产物：迁移框架。
- 验收：旧版样例存档能被识别；不兼容时有明确提示。

## 11. AI 和内容模块 `AI_CONTENT`

### AIC-001 定义 AI 使用的球局查询接口

- 优先级：P2
- 依赖：RUL-001、PHY-021
- 工作：提供合法球、当前比分、球位和可用器材查询。
- 产物：只读 AI 状态接口。
- 验收：AI 不直接修改物理球状态。

### AIC-002 创建候选击球描述

- 优先级：P2
- 依赖：AIC-001、PHY-009
- 工作：描述目标球、袋口、方向、打点和力度范围。
- 产物：`ShotCandidate`。
- 验收：候选击球可转换为普通玩家使用的 `ShotInput`。

### AIC-003 实现单步物理评估

- 优先级：P2
- 依赖：AIC-002、REP-002
- 工作：用同一物理核心评估候选击球结果。
- 产物：AI 评估器。
- 验收：AI 评估结果与回放结果使用相同事件。

### AIC-004 实现基础得分 AI

- 优先级：P2
- 依赖：AIC-003、RUL-005
- 工作：选择简单合法进攻球并完成击球。
- 产物：训练 AI。
- 验收：AI 不会通过瞬移或直接计分完成击球。

### AIC-005 实现防守和风险权重

- 优先级：P3
- 依赖：AIC-004
- 工作：为安全球、落袋概率和留球位置加入权重。
- 产物：难度参数。
- 验收：不同难度表现出可解释的选择差异。

## 12. 性能、发布和联机预研模块 `RELEASE`

### REL-001 建立物理性能采样

- 优先级：P1
- 依赖：PHY-021、PRE-001
- 工作：记录每物理步、每杆、每类碰撞的耗时。
- 产物：Unreal Insights 标记、CSV 采样和报告模板。
- 验收：可以定位最慢的物理步骤和碰撞类型。

### REL-002 建立长杆稳定性测试

- 优先级：P1
- 依赖：VAL-009、REP-002
- 工作：连续运行大量固定击球和随机合法击球。
- 产物：稳定性测试脚本和报告。
- 验收：无内存增长、无永久卡死、无未处理异常。

### REL-003 建立目标硬件测试表

- 优先级：P1
- 依赖：REL-001
- 工作：定义目标 CPU/GPU、分辨率、帧率和物理耗时指标。
- 产物：性能基线表。
- 验收：至少一台目标机器完成完整击球循环测试。

### REL-004 建立异常快照收集

- 优先级：P1
- 依赖：PHY-020、REP-001
- 工作：异常时保存输入、快照、参数和日志。
- 产物：故障包目录格式。
- 验收：开发者拿到故障包即可复现或定位失败步。

### REL-005 建立打包配置

- 优先级：P1
- 依赖：FND-004、REL-003
- 工作：配置 Development、Test 和 Shipping 打包档案。
- 产物：可重复打包配置。
- 验收：干净环境能够生成可启动构建。

### REL-006 建立联机同步设计文档

- 优先级：P3
- 依赖：REP-002、REL-004
- 工作：说明输入同步、物理快照、回滚/重演、延迟和版本一致性。
- 产物：联机技术设计，不立即实现完整联机。
- 验收：文档明确哪些状态同步、哪些状态本地重建，以及版本不一致如何拒绝连接。
